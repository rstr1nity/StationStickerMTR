## Где остановились

На пользовательской карте проверены английские названия, LED-табло без вопросительных знаков, список станций и выбор линии на двух уровнях. Номера в кружках берутся из номера маршрута MTR: после заполнения поля номера появились. Пользователь разрешил выпуск 2.0.0 на GitHub; публикация на Modrinth и CurseForge выполняется отдельно.

Проверки перехода слайдов, локализации и порта 1.19.2 закрыты по решению пользователя.

Сделано 2026-10-27 (вечер): шаблон «Выход в город» (выходы станции MTR, значки MTR из Railway Sign и ресурспаков); ширина навигационной таблички ползунком (общая основа ResizableDisplayBlock); информационный экран (слайды погоды в стиле приложения «Погода» и станции, ширина по умолчанию 2); номер линии ещё из копии дашборда и запоминается; F5 подключает отладчик сам (Gradle --console=plain).

Сделано 2026-10-27 (днём): значок «Посадки нет» без z-fighting; таймер табло снова без сглаживания (по просьбе); на конечной таймер остаётся, «Посадки нет / No Boarding» в строке конечной; названия станций «русское крупно + латиница мелко», латинское — одной строкой; навигационная табличка по центру, стрелка линией с «V», лестница ближе; номер линии в кружках без открытия дашборда (`RouteNumbers`, из прибытий); указатель направлений шириной 2–8 клеток ползунком (кисточка MTR).

## Что известно про MTR (проверено для 4.0.3 по jar через javap и вики)

- Прибытия на клиенте: `ArrivalsCacheClient.INSTANCE.requestArrivals(platformIds)`. Обмен с сервером крутит `MainRenderer.render` каждый кадр — табло PIDS MTR для работы не нужны. Время сервера: `System.currentTimeMillis() + getMillisOffset()`; MTR уточняет время прибытия на лету (отсюда пауза сигнала; сглаживание таймера пробовали и откатили).
- Выходы: `Station.getExits()`, имя = буква + номер («A1»). Окно станции правит копию `MinecraftClientData.getDashboardInstance()`, основная копия обновляется позже - берём из копии дашборда, если там есть. Значки: `CustomResourceLoader.getSortedSignIds()` / `getSignById()`.
- Номер линии: `Route.getRouteNumber()` из `MinecraftClientData.routeIdMap`, но полные маршруты клиент, похоже, получает только при открытии дашборда; запасной источник — `ArrivalResponse.getRouteNumber()` (`RouteNumbers`). В `SimplifiedRoute` номера нет.
- Пересадки: `SimplifiedRoutePlatform.forEach((цвет, названия))` — маршруты других цветов на любой платформе той же станции (скрытые исключены). `Station.getInterchangeStationToColorToRoutesMap` на клиенте в игре вернул пустой список — не используем.
- Станции с пересекающимися областями MTR считает связанными (`connectedStations`, `Station.intersecting`).
- Линия = маршруты одного цвета (точный hex). Два направления — два маршрута с одним цветом. Название: `линия 1|line 1||in` — до `||` языки, после — заметка только для дашборда ([вики: Dashboards](https://wiki.minecrafttransitrailway.com/mtr:dashboards)).
- Всё это внутренние классы `org.mtr.*`: при обновлении MTR проверять заново.

## Как работать

- Запуск: VS Code → «Запустить Minecraft (hot swap)» (F5). Hot swap подхватывает правки внутри методов; новые классы, поля, ресурсы — перезапуск.
- Пока игра запущена, ветку в основной папке не переключать (hot swap подсунет чужой код): 1.19.2 — через временный `git worktree` в scratchpad.
