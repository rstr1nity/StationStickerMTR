- Сигнал `sounds/arrival_chime.ogg` (файл пользователя, моно) за 5 с до прибытия, после — пауза 20 с (`ArrivalChime`). Кисточка MTR включает/выключает (блокстейт `sound`).

## Что известно про MTR 4.0.3 (проверено по jar через javap и вики)

- Прибытия на клиенте: `ArrivalsCacheClient.INSTANCE.requestArrivals(platformIds)`. Обмен с сервером крутит `MainRenderer.render` каждый кадр — табло PIDS MTR для работы не нужны. Время сервера: `System.currentTimeMillis() + getMillisOffset()`; MTR уточняет время прибытия на лету (отсюда пауза сигнала; сглаживание таймера пробовали и откатили).
- Номер линии: `Route.getRouteNumber()` из `MinecraftClientData.routeIdMap`, но полные маршруты клиент, похоже, получает только при открытии дашборда; запасной источник — `ArrivalResponse.getRouteNumber()` (`RouteNumbers`). В `SimplifiedRoute` номера нет.
- Пересадки: `SimplifiedRoutePlatform.forEach((цвет, названия))` — маршруты других цветов на любой платформе той же станции (скрытые исключены). `Station.getInterchangeStationToColorToRoutesMap` на клиенте в игре вернул пустой список — не используем.
- Станции с пересекающимися областями MTR считает связанными (`connectedStations`, `Station.intersecting`).
- Линия = маршруты одного цвета (точный hex). Два направления — два маршрута с одним цветом. Название: `линия 1|line 1||in` — до `||` языки, после — заметка только для дашборда ([вики: Dashboards](https://wiki.minecrafttransitrailway.com/mtr:dashboards)).
- Всё это внутренние классы `org.mtr.*`: при обновлении MTR проверять заново.

## Как работать

- Запуск: VS Code → «Запустить Minecraft (hot swap)» (F5). Hot swap подхватывает правки внутри методов; новые классы, поля, ресурсы — перезапуск.
- Пока игра запущена, ветку в основной папке не переключать (hot swap подсунет чужой код): 1.19.2 — через временный `git worktree` в scratchpad.
